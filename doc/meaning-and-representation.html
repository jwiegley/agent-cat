Meaning and Representation in an Agentic Workflow Calculus

What a workflow denotes, what is written down and executed in its place, and the theorems that bind the second to the first.

This library has two layers and one function between them. The first layer is a meaning: a mathematical object chosen for how well it explains the domain, with no regard for whether it can be computed. The second is a representation: a finite syntax that is written by hand, analysed before it runs, and executed against a live language model. The work consists of proving that every operation of the second commutes with the function into the first.

The order of dependence runs one way. Meaning constrains implementation; implementation does not constrain meaning (Elliott, Denotational Design with Type Class Morphisms, 2009). The sections below give the meaning, the representation, the function joining them, the analyses that only the representation can support, the runtime, and the point at which proof gives way to stated assumption.

Part I The meaning

The design starts from a sentence in the language of the domain: a workflow puts questions to parties that answer, and uses the replies to decide what to ask next. Turning that sentence into mathematics takes two steps. The first fixes where answers come from. The second fixes what a workflow denotes.

Worlds

A world is a total answer sheet: a function holding a reply for every question that could be put.

abbrev Ω : Type := (c : Code) → Q c → El c
-- Agentic/Core/World.lean:47

Here Code names the kinds of answer a question may seek — free text, a review verdict, a yes or no, an acknowledgement — and El gives the type of each. A world is therefore indexed by the question itself, not by any position in a program, and three properties of the domain follow at once.

  • Asking the same question twice yields the same answer. Sharing one consultation among several consumers needs no label, no key, and no dedicated operator.
  • Memoisation is not an optimisation. It is how a runtime builds the world that the semantics quantifies over.
  • A deliberate resample is a different question, distinguished by an index the author writes. A best-of-five is five questions, not one question asked five times.

What a workflow denotes

The obvious candidate, a function from worlds to answers, is too coarse. Under it, a workflow that asks a question, discards the reply, and then asks a second would denote exactly what the second denotes alone; every account of what was consulted, and of what it cost, would be lost. The meaning must record both what came out and what was asked along the way:

⟦ a workflow ⟧  :  Ω → (A × Trace)

For each world, an answer together with the transcript of consultations that produced it. That is the whole of the meaning space. A cost is read off a transcript; a claim such as the guide is consulted once is a claim about a transcript; and both are therefore claims about the denotation rather than remarks about logging.

Where the meaning is defined

Such a function cannot be defined by cases on a workflow, because a workflow is not yet a mathematical object at this stage. It is defined instead on an intermediate carrier, the dialogue, on which structural recursion is available.

inductive Dlg (A : Type) : Type where
  | done : A → Dlg A                                 -- the consultation is complete
  | ask  : (c : Code) → Q c → (El c → Dlg A) → Dlg A  -- put this, and continue from the reply
-- Agentic/Core/Dlg.lean:50

A dialogue is either finished, or a question paired with a continuation for every possible reply. This is the free monad on the question signature, and it is the object known in the semantics literature as a dialogue (Escardó, Continuity of Gödel's system T definable functionals). Two folds now define the meaning, one for each component of the pair:

def run (ω : Ω) : Dlg A → A
  | .done a    => a
  | .ask c q f => run ω (f (ω c q))

def trace (ω : Ω) : Dlg A → Trace
  | .done _    => []
  | .ask c q f => ⟨c, q, ω c q⟩ :: trace ω (f (ω c q))
-- Agentic/Core/Dlg.lean:135, :146

In what sense the folds are the meaning

Calling the pair of folds the meaning is a claim with three separate parts, and each is discharged in the library rather than assumed.

They constitute the semantic function. Together the folds define a single map,

⟦·⟧ : Dlg A → (Ω → A × Trace)        ⟦p⟧ ω = (run ω p, trace ω p)

from the carrier into the meaning space. A dialogue is not itself the meaning; it is what the meaning is computed from.

They respect composition. The folds are monad morphisms, so building a larger workflow from smaller ones corresponds to building its meaning from theirs, and no separate account of sequencing is needed:

theorem run_bind   : run ω (p >>= k) = run ω (k (run ω p))
theorem trace_bind : trace ω (p >>= k) = trace ω p ++ trace ω (k (run ω p))
-- axioms: none

They fix equality. Two workflows are the same workflow when their meanings agree in every world:

Obs p p'  ↔  ∀ ω, run ω p = run ω p' ∧ trace ω p = trace ω p'

This last part carries a consequence worth stating plainly, because it is easy to assume otherwise. The semantic function is not injective: dialogues that differ in structure can agree in every world, and a compiled refutation records an instance. Equality of dialogues is therefore strictly finer than equality of meaning, so Obs is the equality of the domain and the ambient equality of the carrier is not. The benefit of defining it as the kernel of the meaning is that congruence follows directly, with no axioms and no quotient type; the trade-off is that Obs must be written explicitly wherever two workflows are compared.

Part II The representation

A meaning of this kind cannot be examined. The continuation inside a dialogue is a function from an answer type that is not finite, so its branches cannot be enumerated, its questions cannot be listed, and its cost cannot be priced. That is the right posture for a specification and an unusable one for a tool. The representation exists in order to be read, analysed, and executed.

inductive PlanF (A : Type) : Ctx → Type where
  | ret  (e : Expr Γ A)                                                  -- answer with a pure function of what is known
  | askC (c) (q : Q c)                          (k : PlanF A (c :: Γ))   -- a closed question
  | ask  (c) (s : Q.Shape c) (e : Expr Γ String) (k : PlanF A (c :: Γ))  -- words built from earlier answers
  | case (t : Tag) (e : Expr Γ t.El) (arms : t.El → PlanF A Γ)           -- finite branching, every arm present
  | dyn  (b : Code) (e : Expr Γ (El b)) (f : El b → PlanF A Γ)           -- a plan computed from an unbounded answer

abbrev Plan (Γ : Ctx) (A : Type) : Type := PlanF A Γ
-- Agentic/Core/Plan.lean:387, :445

Each node binds the answer it obtains, so a plan reads as a sequence of bindings and the context Γ lists the answers in scope. Two decisions in this type do the work.

First order, with binders

A point-free presentation, built from composition and tupling operators, can be analysed but is hard to read, since the flow of values is expressed in plumbing. A higher-order presentation reads well but cannot be analysed, since a fold over it would need every answer type to be finite, and free text is not. The representation takes neither: it owns the binder. Contexts are lists, variables are indices, and the author writes a binding. Sharing is a variable mentioned twice; branching is case; nothing needs a name.

The shape is written, and only the words are computed

A question divides into two parts. Its shape is everything except the words: who is asked, under which standing conditions, and which draw this is. In an ask node the shape is a term the author writes, and only the prompt is an expression of earlier answers.

Q c  ≅  Q.Shape c × String        -- Agentic/Core/Question.lean:289

It follows that the sequence of question shapes in a run is a projection of the syntax rather than a property to be checked of each workflow: an answer cannot select an addressee, because the node gives it nowhere to go. The benefit is that the cost theorem at the pipeline level carries no hypothesis. The trade-off is that a workflow which genuinely routes to a different addressee on the strength of an answer must say so with a case, where both arms stand in the term and both are priced.

Part III The relation

One function joins the layers. It is defined by structural recursion on the representation, and every theorem in the library is a statement about it.

def denote : Plan Γ A → Env Γ → Dlg A
  | .ret e,       γ => .done (e γ)
  | .askC c q k,  γ => .ask c q                     (fun x => denote k (x ∷ γ))
  | .ask c s e k, γ => .ask c (s.withPrompt (e γ))  (fun x => denote k (x ∷ γ))
  | .case e arms, γ => denote (arms (e γ)) γ
  | .dyn e f,     γ => denote (f (e γ)) γ
-- Agentic/Core/Denote.lean:64
  what is written        where meaning         the meaning itself
                         is computed

   Plan Γ A  ──denote γ──▶  Dlg A  ──⟨run ω, trace ω⟩──▶  A × Trace
                                                            for each ω
The two stages of denotation. The first is defined by recursion on syntax; the second by recursion on the carrier. Their composite is the meaning of a written workflow.

The commuting square

Every way of building a plan has a counterpart way of building a dialogue, and the requirement on each pair is one equation: building and then taking the meaning agrees with taking meanings and then building. This is the square that must commute for each operation.

                        f
        Plan …  ──────────────────▶  Plan Γ B
           │                             │
   denote… │                             │ denote (·) γ
           ▼                             ▼
        Dlg …   ──────────────────▶  Dlg B
                        f̂
f is an operation on plans; f̂ is the corresponding operation on dialogues, taken from a standard structure wherever one exists. The theorem for each row of the table below is the commutativity of this square.

The file holds fifty-five such theorems, one for every operation the surface offers (Agentic/Core/Morphism.lean). Two of them repay a closer reading.

theorem trace_graft (hk : Denotes k K) :
    Plan.trace ω (Plan.graft p k) γ
      = Plan.trace ω p γ ++ Dlg.trace ω (K (Plan.run ω p γ) γ)

theorem denote_panel [Monoid (El c)] (ps : List (Plan Γ (El c))) :
    denote (Plan.panel ps) γ
      = (ps.map (denote · γ)).foldr (fun x y => (· * ·) <$> x <*> y) (pure 1)

The first says that the transcript of a sequence is the concatenation of the transcripts, which is what makes every cost a monoid homomorphism on traces. The second says that a review panel is convolution: the reviewers' meanings combined by lifting the product of the verdict monoid across them. Verdicts form a monoid in which approval is the unit and any objection carries, so the panel needs no reducer of its own and inherits its laws from the standard library.

One equation is absent from the table because it needs no proof. Running a plan is defined as running its denotation, Plan.run ω p γ := Dlg.run ω (denote p γ) (Denote.lean:106), so the square for execution commutes by reflexivity. There is no second semantics to reconcile.

Part IV The difference, and what it purchases

The layers are not two encodings of one thing. Each supports something the other cannot, and the design rests on the asymmetry.

The meaning supportsThe representation supports
Quantification over every world: in all ω, the guide is consulted exactly once. Folding: the level, the sequence of shapes, and the cost tree are computable functions of a term.
The definition of equality, since two workflows are the same when their meanings agree. Typing by context, so no answer can be mentioned before it arrives.
Being infinite and uncomputable without embarrassment: a specification that cannot run cannot be mistaken for the artefact it constrains. Execution, by an interpreter that opens a connection to a live agent.
Indifference to scheduling, caching, retry, and transport. Distinctions the meaning declines to record.

The last row governs the analyses, and one example shows why it matters. In denote, the clause for case and the clause for dyn are the same clause: the two nodes mean exactly the same thing. They differ only in what can be established about them, since case carries every arm in the term while dyn carries a function. Keeping the distinction in the syntax is possible because the meaning does not record it. A representation may know more than its meaning; it may never mean anything other than its meaning.

The four levels

The level of a plan is a fold over the term, not an index in its type (Level.lean:120). A fold leaves the syntax free of proof obligations and puts the whole analysis in ordinary functions.

LevelMark in the termWhat is established about cost
batchclosed questions onlyThe question list is fixed by the term; the bill is exact and the same in every world.
pipelinewords built from answersThe shape sequence is a projection of the syntax; the bill is exact when prices depend on shape.
branchfinite branchingA finite cost tree exists; every world's bill is one of its leaves, and folds give the extremes.
dynamica plan from an unbounded answerA non-existence theorem, witnessed by a plan whose bills are unbounded.

The hierarchy restricts nothing that may be written. It states what may be known about what has been written, and it is graded so that the common case, a prompt assembled from an earlier answer, is priced exactly rather than surrendered to the general case.

Part V Execution, and three statements of correctness

The runtime is a third layer and is deliberately thin. One module speaks line-delimited JSON-RPC over the streams of a child process to an adapter of the Agent Client Protocol, which drives an agent under the operator's own credentials; it makes no semantic claim. A second is the memoising interpreter, factored so that the whole of IO in the construction is one oracle.

oracle : (c : Code) → Q c → IO (El c)      -- render, put the question, decode the reply
exec   : Plan [] A → StateT Table IO A      -- the fold, carrying a table of answers

The table is not a cache attached to an interpreter. It is a finite world under construction, and recording an answer is proved to be the same operation as pinning a cell of a world. Correctness is then carried by three statements, in decreasing strength and increasing contact with reality.

First · the interpreter is the fold

theorem Plan.execWith_eq_execM_denote :
    execWith o p γ t = execM o (denote p γ) t
-- proof: rfl.  axioms: none

The interpreter does not agree with the semantics; it is the semantics, supplied with an oracle. Nothing is proved here because nothing was ever distinct.

Second · adequacy, against an arbitrary answerer

theorem Plan.adequacy (o : Oracle Id) (h : execWith o p ∅ nil = (a, t)) :
    (∀ ω, Extends ω t → Plan.run ω p ∅ = a) ∧
    (∀ ω, Extends ω t → Plan.trace ω p ∅ = Plan.trace (worldOf t) p ∅)
-- Agentic/Core/Certify.lean:130.  axioms: [propext]

The answering party is an arbitrary history-dependent strategy, free to drift, to contradict itself, and to answer differently on different occasions; the theorem assumes nothing to the contrary. It states that the table a run produces is a finite world, and that every total world extending it evaluates the plan to exactly the value the run reported. Non-determinism at the edge is absorbed by quantification rather than by assumption.

Third · the certificate, as a warrant for one run

def certify (p : Plan [] A) (t : Table) (a : A) : Bool :=
  decide (Plan.run (worldOf t) p ∅ = a)

theorem certify_sound : certify p t a = true → ∃ ω : Ω, Plan.run ω p ∅ = a
-- Agentic/Core/Certify.lean:164, :175.  axioms: none

No theorem governs what a live process writes to a pipe, and none is asserted. Each execution instead replays its own log as a world, evaluates the plan purely, and compares. A certificate of true exhibits a world in which the plan means what the run reported, and the soundness proof reaches nothing that could carry an axiom. Completeness holds as well, so a run of this interpreter always certifies. Both axiom claims are pinned in the source, which makes any drift a build failure.

Part VI A worked workflow and its theorems

The worked example is a patch-hardening workflow of about a dozen lines: draft under a designated model; submit the draft to three reviewers, two of whom share one reading of a style guide; revise up to twice on objection; put the question of consent to a person; and apply only upon assent.

Its theorems fall into three kinds, and the distinction is the point of the whole construction, so each is marked in the table below. A meaning theorem quantifies over worlds and speaks only of run and trace; the workflow appears in it as a term, but every predicate applied to it belongs to the meaning space. A representation theorem is a computation on the term itself, decided by evaluation. A bridge theorem connects the two, and is what allows a computation on syntax to be believed about all worlds.

TheoremKindContent
denote_hardenPatchbridge The denotation of the written workflow is a particular dialogue, given independently. Every meaning theorem below is proved by rewriting with this equation and then reasoning in the meaning space alone.
consent_of_ackmeaning Should any acknowledgement appear in the transcript, in any world, the owner answered affirmatively concerning some patch.
ack_quotes_consented_patchmeaning The patch acknowledged is the patch consented to; the two are the same patch, not merely both present.
guide_oncemeaning The style guide is consulted exactly once in every world. Sharing, stated as a count.
draft_count_le_threemeaning At most three drafts are requested, in every world.
level_hardenPatchrepresentation The level fold returns branch, by reflexivity. A fact about the term, and of interest only because the soundness theorems attach cost results to that level.
card_leaves, minFold, maxFoldrepresentation The cost tree computed from the term has nine leaves, with extremes 5 and 15, decided by evaluation.
bill_hardenPatchmeaning In every world the bill read from the transcript is one of {6, 7, 10, 11, 13, 14, 15}, with a world exhibited for each end of the range.
minFold_not_attainedmeaning No world attains the tree's minimum of 5. The computed bound is sound and slack by one consultation, and the slack is recorded rather than elided.

The pattern is worth stating in general. A property of interest is proved in the meaning space, where worlds can be quantified over and nothing depends on how the workflow was written. An analysis is computed in the representation, where a term can be folded. A bridge theorem, or a soundness theorem for the analysis, is what permits the second to be read as evidence about the first. Neither layer is asked to do the other's work.

Execution against a live agent

The same plan executes against Claude Code through an Agent Client Protocol adapter, in a scratch directory, with the consent question routed to the keyboard. One run consumed seven consultations over roughly eighty-four seconds:

tool cat                 (text)     Write out the house style guide…   -> Lead with the outcome…
model author   model=deep (text)    Draft a patch satisfying…          -> a unified diff, bounds-checked
model reviewer-correct   (verdict)  …is this patch correct?            -> approve
model reviewer-secure    (verdict)  …is this patch secure?             -> approve
model reviewer-simple    (verdict)  Could this patch be simpler?       -> approve
person owner             (flag)     Apply this patch?                  -> yes
tool apply               (ack)      Apply: …                           -> done

bill: 7 consultations        ok  bill ∈ [6,7,10,11,13,14,15]
ok  the guide was read exactly once         ok  at most three drafts
ok  consent ⇔ the apply question was put    ok  the act wrote the consented patch
ok  the run certifies

The replies of a live model constitute one world among many, which is why the theorems transfer to it without weakening. Had a reviewer objected, the run would have taken a revision round and landed on a different member of the same proved set. The file left in the scratch directory was hardened in fact: the parsing routine now accepts buffer sizes and bounds every copy. A second run, differing only in the answer to the consent question, consumed six consultations, produced no acknowledgement, and left the file untouched.

Part VII The boundary of proof

A proof is informative in proportion to the clarity of its boundary. Four things are trusted, and each is stated in the source rather than hidden inside a theorem.

  • The decoders. One total parser attends each kind of answer. How a particular English sentence divides into words is not something the kernel can settle, so sixteen measured replies are pinned as tests. The parser fails closed: a word of refusal anywhere denies, while assent must be the whole reply, since no rule admitting Yes, apply it can exclude I cannot approve this patch.
  • Adapter fidelity. That the process at the far end of the pipe relays the model faithfully is an empirical assumption, and it is labelled as one.
  • The permission grant. The runtime authorises tool calls within the working directory of its own session. Refusing them is not the conservative choice it appears to be: a refused permission does not end the turn, which completes normally with prose in place of an act, at considerable cost and with no signal in the protocol to distinguish it from an answer.
  • The log. The certificate warrants a claim about the table a run recorded, from which one rule follows without exception: nothing may be written into the table that no party said. When decoding fails after its retries the run is abandoned and the unreadable reply is quoted, because a defaulted answer in a table without provenance cannot be told from an answer given.

Coda

Three layers, one function between the first two, and one oracle between the second and the world:

A meaning: for each world, an answer and a transcript, computed by two folds over a carrier that exists only to make the definition compositional.
A representation: first-order, with binders, each of whose operations is proved to commute with its meaning, and whose surplus structure funds the analyses.
A runtime: the same fold supplied with an oracle, each of whose runs carries a decidable certificate of agreement with the mathematics.

What the arrangement buys is the property the discipline exists to secure: a workflow value may be treated as being its meaning. When a run reports that the guide was consulted once, that is not an observation about the run. It is a theorem about every world, and the run is evidence that the machinery beneath the theorem told the truth.
