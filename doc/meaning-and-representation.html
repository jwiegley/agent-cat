The Meaning and the Representation

What an agentic workflow is as a mathematical object, what we actually write down and run, and the theorems that hold the two together.

There are two objects in this design and it is important never to confuse them. The first is a meaning: a mathematical thing that exists whether or not any computer runs, chosen for how well it explains the domain and not for how well it executes. The second is a representation: a finite piece of syntax we type into a file, analyse offline, and hand to an interpreter that talks to a real model over a socket. Between them runs a single function, and the whole discipline consists of proving that every operation on the second commutes with that function into the first.

The asymmetry is the doctrine, in Conal Elliott's words: meaning constrains implementation; implementation never constrains meaning. What follows is the state of that construction as it now stands in ~/src/agent-cat — 7,853 lines of Lean across twelve modules, 419 theorems, zero sorry, and a demo that drives Claude Code over ACP and produces a certificate the kernel checks.

Part I The meaning: worlds and dialogues

Step one of the method is a sentence in the domain's own words, before any type: a workflow puts questions to things that answer — models, tools, people — and uses what comes back to decide what to ask next. Step two is the question that shapes everything: a workflow is a representation of what mathematical object?

The world

Everything hangs on one modelling decision, and it is the decision our first attempt got wrong. A world is not a log, not a sequence of events, not a state machine. It is a total answer sheet: a function that has an answer ready for every question that could possibly be put.

abbrev Ω : Type := (c : Code) → Q c → El c
-- Agentic/Core/World.lean:47

Code is the small closed universe of answer kinds — text, verdict, flag, ack — and El sends each to what an addressee can say: String, Verdict, Bool, Unit. A question Q c carries its addressee, its standing scope, its words, and a draw index. Because a world is a function of the question, three domain facts stop being features and become theorems:

  • Asking the same question twice gives the same answer — so sharing costs nothing to state. There are no labels, no keys, no share combinator anywhere in the library. Sharing a style guide between two reviewers is a variable used twice.
  • Caching is not an optimisation. Memoisation is how the runtime constructs the world the semantics quantifies over — the interpreter's answer table is a finite world.
  • Deliberate resampling must be a different question, which is what the draw index is for. Best-of-five is five questions, not one question asked five times.

The failed morphism that fixed the design

Our previous specification indexed worlds by positions in the syntax tree — inherited, we later established, from an interpreter's node-ids in a Haskell codebase we had studied first. Every unresolved problem in that library traced to it: label collisions kept honest by a docstring, a quotient that could not finish, two meaning functions that contradicted each other. Re-deriving from the domain rather than the codebase produced Ω above, and the problems did not get solved — they ceased to exist.

The dialogue

A workflow's meaning cannot be merely Ω → A. That collapses too much: ask q then ignore the answer and ask q' would mean the same as ask q' alone, and no compositional cost analysis can exist over such a meaning. What the domain needs is the pair (what you end up with, what you consulted to get there) — and the solved form of that pair is a tree:

inductive Dlg (A : Type) : Type where
  | done : A → Dlg A                                -- the dialogue is over
  | ask  : (c : Code) → Q c → (El c → Dlg A) → Dlg A -- put this, continue with whatever comes back
-- Agentic/Core/Dlg.lean:50

This is the free monad on the question signature — in the semantics literature, Escardó's dialogue; in type theory, a W-type. It is not a data structure chosen for convenience; it is what "a computation that consults an oracle" is. Two folds read it, and together they are the meaning:

def run (ω : Ω) : Dlg A → A
  | .done a    => a
  | .ask c q f => run ω (f (ω c q))

def trace (ω : Ω) : Dlg A → Trace
  | .done _    => []
  | .ask c q f => ⟨c, q, ω c q⟩ :: trace ω (f (ω c q))

The transcript lives inside the meaning, which is what lets a sentence like "in every world where the owner says no, the apply question is never put" be a mathematical statement rather than a remark about logging. And both folds are monad morphisms, proved:

theorem run_bind   : run ω (p >>= k) = run ω (k (run ω p))
theorem trace_bind : trace ω (p >>= k) = trace ω p ++ trace ω (k (run ω p))
-- axioms: none

Equality, and a lemma that turned out false

The kernel we synthesised claimed a Forcing Lemma: that equality of dialogue trees coincides with agreement of (run, trace) in every world. We tried to prove it and could not — because it is false, and the refutation is compiled (Dlg.not_forcing): two structurally different trees can agree in every world when a question is asked twice and the second answer is ignored. So semantic equality is defined as the kernel of the meaning,

Obs p p'  ↔  ∀ ω, run ω p = run ω p' ∧ trace ω p = trace ω p'

and Obs.bind_congr — congruence, the thing our earlier quotient-based design had to prove clause by clause and never finished — falls out with no axioms at all. A failed morphism is not a setback in this method. It is the most informative output it produces.

Part II The representation: plans

The meaning is uncomputable in the ways that matter — a Dlg's continuation is a Lean function from an infinite answer type, so you cannot look inside it, enumerate its branches, or price it. That is exactly right for a specification and useless for a tool. The representation exists to be looked at.

inductive Plan : Ctx → Type → Type 1 where
  | ret  (e : Expr Γ A)                                             -- a pure function of what is known
  | askC (c) (q : Q c)             (k : Plan (c :: Γ) A)            -- a closed question
  | ask  (c) (s : Q.Shape c) (e : Expr Γ String) (k : Plan (c :: Γ) A) -- words built from earlier answers
  | case (e : Expr Γ T) (arms : T → Plan Γ A)  [FinEnum T]          -- finite branching, every arm present
  | dyn  (e : Expr Γ (El c)) (f : El c → Plan Γ A)                  -- quarantined: a plan from an unbounded answer
-- Agentic/Core/Plan.lean:197

Three design decisions in this type are worth naming, because each was forced by something that failed first.

It is first-order, with binders

A point-free arrow calculus (>>>, &&&, tuple plumbing) is analysable but unreadable — you cannot find your workflow in it. A higher-order encoding is readable but unanalysable — cost on it demands finiteness of every answer type, which free text does not have. The dilemma is false: own the binder. Contexts are lists of codes, variables are de Bruijn indices, and the author writes let. Sharing is a variable used twice; branching is case; nothing needs a label.

The shape is data; only the words are computed

The kernel's cost theorem for the pipeline level was false when ask carried an arbitrary expression of question-space: an answer could then select the addressee, and the sequence of question shapes stopped being a fact about the term. We repaired it in the representation rather than with a side condition. Q c ≅ Q.Shape c × String; the author writes the shape in the term and only the prompt flows from earlier answers, because there is no place in the node for anything else to flow. A predicate that had to be discharged for every workflow was deleted outright, and the shape sequence became a computable projection of the syntax.

FinEnum, not Fintype — a detail that pays a debt three modules away

Mathlib's Fintype holds a Finset, which holds a Multiset, which is a quotient. A syntax whose branching node mentions it would depend on propext and Quot.sound as a type, before any theorem is stated — and the zero-axiom claim for the runtime certificate in Part VI is a claim about the whole transitive graph. FinEnum says the same thing out of Fin, Equiv and List, none of which is a quotient.

Part III How they relate: one fold

The two objects are joined by a single function, defined by structural recursion, and everything else in the library is a theorem about it.

def denote : Plan Γ A → Env Γ → Dlg A
  | .ret e,        γ => .done (e γ)
  | .askC c q k,   γ => .ask c q               (fun x => denote k (x ∷ γ))
  | .ask c s e k,  γ => .ask c (s.withPrompt (e γ)) (fun x => denote k (x ∷ γ))
  | .case e arms,  γ => denote (arms (e γ)) γ
  | .dyn e f,      γ => denote (f (e γ)) γ
-- Agentic/Core/Denote.lean:64
            THE REPRESENTATION                    THE MEANING
         (finite, inspectable, typed)        (infinite, uncomputable, true)

              Plan Γ A  ──────────── denote ───────────▶  Dlg A
                 │                                          │
     level, shapes, costTree                          run ω, trace ω
                 │                                          │
                 ▼                                          ▼
          Level, CostTree, bills   ◀── sound by C0–C5 ──   A × Trace
                 │                                          ▲
              exec ⟨oracle⟩                                 │
                 │                                          │
                 ▼                    certify (decidable)   │
        IO: ACP ⇄ Claude Code  ───────── warrants ──────────┘
              (a real world)

Notice what the diagram does not contain: a second semantics. Running a plan is defined as running its denotation —

def Plan.run ω p γ := Dlg.run ω (denote p γ)

— so the commutation between interpreter and meaning is rfl. There is nothing to reconcile because there was never anything to reconcile.

The commuting squares

Morphism.lean is 55 theorems, one per operation, each the literal statement that the operation commutes with denote. A representative selection, verbatim:

theorem denote_graft (hk : Denotes k K) :
    denote (Plan.graft p k) γ = denote p γ >>= fun a => K a γ

theorem trace_graft (hk : Denotes k K) :
    Plan.trace ω (Plan.graft p k) γ
      = Plan.trace ω p γ ++ Dlg.trace ω (K (Plan.run ω p γ) γ)

theorem denote_panel [Monoid (El c)] (ps : List (Plan Γ (El c))) :
    denote (Plan.panel ps) γ
      = (ps.map (denote · γ)).foldr (fun x y => (· * ·) <$> x <*> y) (pure 1)

theorem run_under (σ : Sig) :
    Plan.run ω (Plan.under σ p) γ = Plan.run (fun c q => ω c (σ.onQ c q)) p γ

Read them as sentences. Sequencing a plan is monadic bind, and its transcript is concatenation. A review panel is convolution in the verdict monoid — the applicative lifting of multiplication over the reviewers' meanings, which is exactly what "any objection carries" means when the verdict monoid is WithZero (FreeMonoid Objection) with approve = 1. Putting a workflow under a model scope is reindexing the world. Bounded revision is the check-then-revise unrolling of the loop — and note the order: the artifact you end up with has always been reviewed, a bug all three of our independent derivations wrote backwards before the adversarial pass caught it.

Part IV How they differ

They are not two encodings of the same thing. Each can do something the other structurally cannot, and the design lives on that difference.

The meaning canThe representation can
Quantify over all worlds: "in every ω, the guide is consulted exactly once." Be folded: level, shapes, costTree are computable functions of a term.
Define equality: two workflows are the same when their meanings agree (Obs). Be typed by its context, so an author cannot mention an answer that has not arrived.
Be infinite and uncomputable without embarrassment — a specification that cannot run cannot be mistaken for the artifact it constrains. Be executed: handed to an interpreter that opens a socket.
Ignore how anything is scheduled, cached, retried, or transported. Record distinctions the meaning deliberately forgets — most importantly, the difference between case and dyn.

That last row is the subtle one and it is where the analysis stratum comes from. denote (case e arms) γ and denote (dyn e f) γ are the same clause: the two nodes are indistinguishable in meaning. They differ only in what can be said about them — case has every arm in the term, dyn has a function. Keeping the distinction in the syntax is possible precisely because the meaning does not record it. The representation is allowed to know more than the meaning, so long as it never means anything different.

The four rungs, and what each buys

The level of a plan is a fold, never a type index — a compiled probe established that Lean's dependent elimination refuses computed indices, which killed the graded-inductive design before a line of it was written.

LevelSyntactic markWhat is proved about cost
batchonly closed questionsThe question list is fixed by the term. Exact bill, world-independent.
pipelinewords built from answersThe shape sequence is a projection of the syntax; exact bill under PricesByShape.
branchfinite-tag caseA finite CostTree; every world's bill is one of its leaves; tropical folds give min and max.
dynamicdynAn honest non-existence theorem, with a witness whose bills are unbounded.

This is the answer to the requirement that monad be retained only where genuinely needed: the hierarchy is not a restriction on what you may write, it is a statement of what may be known about what you wrote.

Part V The third layer: execution

The runtime is a third stratum, and it is deliberately thin. Acp.lean speaks line-delimited JSON-RPC over a child process's stdio to a real adapter — claude-agent-acp driving Claude Code, or codex-acp driving Codex. It makes no semantic claims and its docstring says so. Exec.lean is the memoising interpreter, factored so that the only IO in the entire construction is a single oracle function:

oracle : (c : Code) → Q c → IO (El c)     -- render, prompt, decode
exec   : Plan [] A → StateT Table IO A     -- the fold, with a memo table

The table is not a cache bolted onto a runtime. It is a finite world under construction — and worldOf_cons, proved in World.lean, says that recording an answer and pinning a cell are the same operation seen at two levels.

Part VI How correctness is proved

Three statements, in decreasing strength and increasing contact with reality. Together they are the answer to "how do you know the implementation is right?"

1 · The interpreter is the fold

theorem Plan.execWith_eq_execM_denote : execWith o p γ t = execM o (denote p γ) t
-- proof: rfl.   axioms: none

Not "the interpreter agrees with the semantics" — the interpreter is the semantics, applied to an oracle. Nothing is proved because nothing was ever separate.

2 · Adequacy, against an adversarial answerer

theorem Plan.adequacy (o : Oracle Id) (h : execWith o p ∅ nil = (a, t)) :
    (∀ ω, Extends ω t → Plan.run ω p ∅ = a) ∧
    (∀ ω, Extends ω t → Plan.trace ω p ∅ = Plan.trace (worldOf t) p ∅)
-- axioms: [propext]

The answering process is an arbitrary history-dependent strategy: it may drift, contradict itself, or answer differently at different times. The theorem does not assume otherwise. It says the run's own table is a finite world, and every total world extending it evaluates the plan to exactly what the run reported. Non-determinism at the edge is absorbed by quantification, not by assumption.

3 · The certificate — the per-run warrant

def certify (p : Plan [] A) (t : Table) (a : A) : Bool :=
  decide (Plan.run (worldOf t) p ∅ = a)

theorem certify_sound : certify p t a = true → ∃ ω : Ω, Plan.run ω p ∅ = a
-- axioms: NONE  (#guard_msgs-pinned: a build failure if it ever drifts)

No theorem can govern what a live process writes to a pipe, so we do not axiomatise one. Instead every execution replays its own log as a world, evaluates the plan purely, and compares. A true certificate exhibits a world in which the plan means what the run said it means — and the proof of that reaches nothing which could carry an axiom. Completeness holds too (certify_execWith): a run of this interpreter always certifies.

The flagship, and what it says about your workflow

Twelve lines of do-notation — draft under a deep model, three reviewers sharing one reading of a style guide, revise up to twice, ask the owner, apply only on yes — written as a Plan, with these proved about its meaning. Every statement quantifies over worlds; none mentions syntax.

The live run

On 13 August 2026 this executed against Claude Code over ACP — seven consultations, 83.5 seconds, in a scratch directory, with consent read from the keyboard:

A real model's answers are simply some world. That is why the theorems transfer without weakening: had the reviewers objected, the run would have taken a revise round — a different proved-reachable world, with its bill still in the set. The file left in the scratch directory was genuinely hardened: parse_line rewritten to take buffer sizes with every copy bounds-checked, no strcpy.

Part VII What is assumed, honestly

A proof is only as interesting as its boundary is explicit. Four things are trusted, and none of them is hidden inside a theorem.

  • The decoders. One total parser per code — how a particular English sentence tokenizes cannot be proved, only tested, and sixteen measured replies are pinned in the test suite. This boundary bit back: a lenient decoder read "I cannot approve this patch." as consent. It now fails closed — a refusal word anywhere denies; a yes must be the whole reply.
  • Adapter fidelity. That the process on the other end of the pipe relays the model faithfully. Stated as an empirical assumption, never as an axiom.
  • The permission grant. The runtime allows tool calls inside its own scratch directory. Discovered the hard way: answering the permission request with a JSON-RPC error does not end the turn — the model apologises for 97,000 tokens and the act silently does not happen. A stub could never have found that.
  • The log. The certificate's warrant is about the table the run recorded. So the runtime is forbidden to write into it anything nobody said: when decoding fails, the run is abandoned, quoting the unreadable reply. An earlier version recorded a default — indistinguishable, in a table with no provenance, from an answer someone gave. The fix went at the point of the cons, and the semantic object stayed pure.

Coda The shape of the thing

Three strata, one function between the first two, one oracle between the second and the world:

A meaning — total answer sheets and the dialogues that consult them — chosen for comprehension, uncomputable on purpose.
A representation — first-order plans with binders, whose every operation is proved to commute with its meaning, and whose extra structure buys analyses the meaning cannot support.
A runtime — the same fold with an oracle in IO, whose every run carries a decidable certificate that it agreed with the mathematics.

What this buys, in the end, is the property the whole discipline exists for: you may treat a workflow value as being its meaning. When the demo says the guide was read once, that is not an observation about one run — it is a theorem about all of them, and the run is a confirmation that the machinery below the theorem told the truth.
