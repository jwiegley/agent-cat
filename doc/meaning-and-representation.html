Meaning and Representation in an Agentic Workflow Calculus

What a workflow denotes, what is written down and executed in its place, and the theorems that bind the second to the first.

This document describes a library in two layers and the function that joins them. The first layer is a meaning: a mathematical object chosen for how faithfully it explains the domain, without regard for whether it can be computed. The second is a representation: a finite syntax that is written by hand, analysed before it runs, and interpreted against a live language model over a socket. The discipline consists of proving that every operation of the second commutes with the function into the first, so that a workflow value may be treated as being its meaning.

The order of dependence runs one way and never the other: meaning constrains implementation, and implementation does not constrain meaning (Elliott, Denotational Design with Type Class Morphisms, 2009). The account below covers the meaning space, the representation, the relation between them, the analyses the representation supports, the runtime that executes it, and the boundary at which proof gives way to stated assumption.

Part I The meaning

The design begins with a sentence in the vocabulary of the domain rather than with a type: a workflow puts questions to parties that answer — models, tools, and people — and uses the replies to determine what to ask next. Two mathematical objects answer that sentence. The first is the space in which answers live; the second is the shape of a consultation.

Worlds

A world is a total answer sheet: a function that holds a reply ready for every question that could be put.

abbrev Ω : Type := (c : Code) → Q c → El c
-- Agentic/Core/World.lean:47

Code is a small closed universe of answer kinds — text, verdict, flag, and ack — and El assigns to each the type of what an addressee may say: String, Verdict, Bool, and Unit respectively (Question.lean:215, :228). A question Q c records its addressee, the standing conditions under which it is put, its words, and a draw index (Question.lean:263). A verdict is an element of WithZero (FreeMonoid Objection), so that approval is the monoid unit, refusal is the absorbing zero, and the combination of several reviewers' verdicts is a product whose laws come from the standard library rather than from a bespoke proof.

Because a world is a function of the question, three properties of the domain become consequences rather than features. Repetition is identity: putting the same question twice yields the same answer, so sharing one consultation among several consumers requires no label, no key, and no dedicated combinator. Memoisation is not an optimisation but the manner in which a runtime constructs the world the semantics quantifies over. Deliberate resampling is a different question, which is the office of the draw index; a best-of-five is five questions rather than one question asked five times.

Dialogues

A workflow cannot denote a bare function from worlds to answers. Such a reading identifies too much: a plan that asks a question, discards the reply, and then asks a second would denote what the second denotes alone, and no compositional account of cost could be built over it. What the domain requires is the pair of the eventual answer and the record of what was consulted to reach it, coherently indexed by the world. The solved form of that pair is a tree.

inductive Dlg (A : Type) : Type where
  | done : A → Dlg A                                 -- the consultation is complete
  | ask  : (c : Code) → Q c → (El c → Dlg A) → Dlg A  -- put this, and continue from the reply
-- Agentic/Core/Dlg.lean:50

This is the free monad on the question signature, known in the semantics literature as the dialogue construction (Escardó, Continuity of Gödel's system T definable functionals) and in type theory as a W-type. Two folds read it, and the pair of them is the meaning:

def run (ω : Ω) : Dlg A → A
  | .done a    => a
  | .ask c q f => run ω (f (ω c q))

def trace (ω : Ω) : Dlg A → Trace
  | .done _    => []
  | .ask c q f => ⟨c, q, ω c q⟩ :: trace ω (f (ω c q))
-- Agentic/Core/Dlg.lean:135, :146

The transcript resides within the meaning rather than beside it in a log. That placement is consequential: it is what permits a sentence such as in every world in which the owner declines, the apply question is never put to be a proposition about the denotation. Both folds are monad morphisms, and both statements are proved:

theorem run_bind   : run ω (p >>= k) = run ω (k (run ω p))
theorem trace_bind : trace ω (p >>= k) = trace ω p ++ trace ω (k (run ω p))
-- axioms: none

Equality

Structural equality on Dlg is strictly finer than agreement of meaning: two trees that differ in shape may agree in run and in trace in every world, and a compiled refutation records the fact. Semantic equality is therefore defined as the kernel of the meaning,

Obs p p'  ↔  ∀ ω, run ω p = run ω p' ∧ trace ω p = trace ω p'

from which congruence follows directly and without axioms (Obs.bind_congr). The benefit of this arrangement is that no quotient type is required and the carrier remains computable; the trade-off is that Obs must be written explicitly in the statement of any theorem that compares two workflows, since the ambient equality of the type is not the equality of the domain.

Part II The representation

A meaning is uncomputable in the respects that matter to a tool: the continuation of a dialogue is a function from an answer type that is not finite, so its branches cannot be enumerated, its questions cannot be listed, and its cost cannot be priced. This is the correct posture for a specification and an unusable one for an artefact. The representation exists in order to be examined.

inductive Plan : Ctx → Type → Type 1 where
  | ret  (e : Expr Γ A)                                                 -- a pure function of what is known
  | askC (c) (q : Q c)                          (k : Plan (c :: Γ) A)   -- a closed question
  | ask  (c) (s : Q.Shape c) (e : Expr Γ String) (k : Plan (c :: Γ) A)  -- words built from earlier answers
  | case (e : Expr Γ T) (arms : T → Plan Γ A) [FinEnum T]               -- finite branching, every arm present
  | dyn  (e : Expr Γ (El c)) (f : El c → Plan Γ A)                      -- a plan computed from an unbounded answer
-- Agentic/Core/Plan.lean:197

Three properties of this type carry the weight, and each is a deliberate trade of one capability for another.

First order, with binders

A point-free arrow presentation admits analysis and resists reading, since the flow of values must be expressed in composition and tupling operators; a higher-order presentation reads well and resists analysis, since a cost fold over it requires finiteness of every answer type, which free text does not provide. The representation takes neither horn: contexts are lists of codes, variables are de Bruijn indices, and the author writes a binding. Sharing is a variable mentioned twice; branching is case; no naming apparatus is required at any point.

The shape is data, and only the words are computed

A question factors as Q c ≅ Q.Shape c × String, the shape carrying the addressee, the scope, and the draw (Question.lean:289). In the ask node the shape is written by the author as a term, and only the prompt is an expression of the answers in scope. It follows that the sequence of question shapes is a projection of the syntax rather than a property to be established of each workflow: an answer cannot select an addressee, because the node affords it nowhere to do so. The benefit is that the pipeline-level cost theorem carries no hypothesis; the trade-off is that a workflow which genuinely routes to a different addressee on the strength of an answer must express that routing as a case, where both arms are present and priced.

FinEnum rather than Fintype

Mathlib's Fintype carries a Finset, which carries a Multiset, which is a quotient. A branching node mentioning it would depend on propext and Quot.sound as a matter of its type, before any proposition about it were stated, and the empty axiom set claimed for the runtime certificate in Part V is a claim about the entire transitive graph. FinEnum expresses the same content — a bijection with Fin n — through Fin, Equiv, and List, none of which is a quotient, and Mathlib derives a Fintype instance from it, so the enumerations used in the analyses are unaffected.

Part III The relation

One function joins the two layers, defined by structural recursion on the representation. Every subsequent theorem in the library is a statement about it.

def denote : Plan Γ A → Env Γ → Dlg A
  | .ret e,       γ => .done (e γ)
  | .askC c q k,  γ => .ask c q                     (fun x => denote k (x ∷ γ))
  | .ask c s e k, γ => .ask c (s.withPrompt (e γ))  (fun x => denote k (x ∷ γ))
  | .case e arms, γ => denote (arms (e γ)) γ
  | .dyn e f,     γ => denote (f (e γ)) γ
-- Agentic/Core/Denote.lean:64
        REPRESENTATION                              MEANING
   finite · inspectable · typed              total · uncomputable · true

        Plan Γ A  ─────────────── denote ──────────────▶  Dlg A
           │                                                │
   level · shapes · costTree                          run ω · trace ω
           │                                                │
           ▼                                                ▼
   Level · CostTree · bills  ◀──── sound, C0–C5 ────    A × Trace
           │                                                ▲
     exec ⟨oracle⟩                                          │
           │                    certify : decidable         │
           ▼                                                │
   IO · ACP ⇄ a live agent ───────── warrants ──────────────┘
        (one particular world)

What the figure omits is as important as what it contains: there is no second semantics. Running a plan is defined as running its denotation, Plan.run ω p γ := Dlg.run ω (denote p γ) (Denote.lean:106), so agreement between the interpreter and the meaning holds by reflexivity. Nothing is reconciled, because nothing was ever separate.

The commuting equations

Morphism.lean holds fifty-five theorems, one for each operation of the representation, each stating that the operation commutes with denote. Four are representative.

theorem denote_graft (hk : Denotes k K) :
    denote (Plan.graft p k) γ = denote p γ >>= fun a => K a γ

theorem trace_graft (hk : Denotes k K) :
    Plan.trace ω (Plan.graft p k) γ
      = Plan.trace ω p γ ++ Dlg.trace ω (K (Plan.run ω p γ) γ)

theorem denote_panel [Monoid (El c)] (ps : List (Plan Γ (El c))) :
    denote (Plan.panel ps) γ
      = (ps.map (denote · γ)).foldr (fun x y => (· * ·) <$> x <*> y) (pure 1)

theorem run_under (σ : Sig) :
    Plan.run ω (Plan.under σ p) γ = Plan.run (fun c q => ω c (σ.onQ c q)) p γ

Each reads as a sentence about the domain. Sequencing one plan after another is monadic bind, and the transcript of the composite is the concatenation of the transcripts. A review panel is convolution in the verdict monoid: the applicative lifting of multiplication across the reviewers' meanings, which is precisely the content of the rule that any objection carries. Placing a workflow under a model scope is a reindexing of the world, so that a scope is a transformation of questions rather than an effect of its own. Bounded revision unrolls as check-then-revise, in that order, so that the artefact finally produced has always been reviewed.

Part IV The difference, and what it purchases

The two layers are not alternative encodings of a single thing. Each supports something the other structurally cannot, and the design rests on that asymmetry.

The meaning supportsThe representation supports
Quantification over every world: in all ω, the guide is consulted exactly once. Folding: level, shapes, and costTree are computable functions of a term.
The definition of equality, since two workflows are the same when their meanings agree. Typing by context, so that no answer may be mentioned before it arrives.
Being infinite and uncomputable without embarrassment: a specification that cannot run cannot be mistaken for the artefact it constrains. Execution, by an interpreter that opens a connection to a live agent.
Indifference to scheduling, caching, retry, and transport. Distinctions the meaning declines to record, of which case against dyn is the most consequential.

The final row governs the analyses. In denote, the clause for case and the clause for dyn are the same clause: the two nodes are indistinguishable in meaning, and differ only in what may be established about them, since case carries every arm in the term while dyn carries a function. Retaining the distinction in the syntax is possible because the meaning does not record it. A representation may know more than its meaning; it may never mean anything other than its meaning.

The four rungs

The level of a plan is a fold rather than a type index (Level.lean:120). The arrangement is deliberate: an index computed from a term obstructs dependent elimination in Lean, whereas a fold leaves the syntax free of proof obligations and places the entire analysis in ordinary functions.

LevelSyntactic markWhat is established about cost
batchclosed questions onlyThe question list is fixed by the term; the bill is exact and world-independent.
pipelinewords built from answersThe shape sequence is a projection of the syntax; the bill is exact under PricesByShape.
branchfinite-tag caseA finite CostTree exists; every world's bill is one of its leaves, with tropical folds giving the extremes.
dynamicdynA non-existence theorem, witnessed by a plan whose bills are unbounded.

The hierarchy imposes no restriction on what may be written. It states what may be known about what has been written, and it is graded so that the common case — a prompt assembled from an earlier answer — is priced exactly rather than surrendered to the general case.

Part V Execution, and the three statements of correctness

The runtime forms a third layer and is deliberately thin. Acp.lean speaks line-delimited JSON-RPC over the standard streams of a child process to an adapter of the Agent Client Protocol, which drives an agent under the operator's own credentials; the module makes no semantic claim, and its documentation says so. Exec.lean is the memoising interpreter, factored so that the whole of IO in the construction is a single oracle.

oracle : (c : Code) → Q c → IO (El c)      -- render, put the question, decode the reply
exec   : Plan [] A → StateT Table IO A      -- the fold, carrying a table of answers

The table is not a cache attached to an interpreter. It is a finite world under construction, and worldOf_cons establishes that recording an answer and pinning a cell are one operation observed at two levels. Correctness is then carried by three statements, in decreasing strength and increasing contact with the world.

First · the interpreter is the fold

theorem Plan.execWith_eq_execM_denote :
    execWith o p γ t = execM o (denote p γ) t
-- proof: rfl.  axioms: none

The interpreter does not agree with the semantics; it is the semantics, supplied with an oracle. Nothing is proved here because nothing was ever distinct.

Second · adequacy, against an arbitrary answerer

theorem Plan.adequacy (o : Oracle Id) (h : execWith o p ∅ nil = (a, t)) :
    (∀ ω, Extends ω t → Plan.run ω p ∅ = a) ∧
    (∀ ω, Extends ω t → Plan.trace ω p ∅ = Plan.trace (worldOf t) p ∅)
-- Agentic/Core/Certify.lean:130.  axioms: [propext]

The party answering is an arbitrary history-dependent strategy, at liberty to drift, to contradict itself, and to answer differently on different occasions; the theorem assumes nothing to the contrary. It states that the table produced by a run is a finite world, and that every total world extending it evaluates the plan to exactly the value the run reported. Non-determinism at the edge is absorbed by quantification rather than by assumption.

Third · the certificate, as a warrant for one run

def certify (p : Plan [] A) (t : Table) (a : A) : Bool :=
  decide (Plan.run (worldOf t) p ∅ = a)

theorem certify_sound : certify p t a = true → ∃ ω : Ω, Plan.run ω p ∅ = a
-- Agentic/Core/Certify.lean:164, :175.  axioms: none

No theorem governs what a live process writes to a pipe, and none is asserted. Each execution instead replays its own log as a total world, evaluates the plan purely, and compares: a certificate of true exhibits a world in which the plan means what the run reported it to mean, and the proof of soundness reaches nothing capable of carrying an axiom. Completeness holds as well, so a run of this interpreter always certifies. Both axiom claims are pinned by #guard_msgs, which renders any drift a build failure.

Part VI A worked workflow and its theorems

The flagship is a patch-hardening workflow of about a dozen lines: draft under a designated model, submit the draft to three reviewers of whom two share one reading of a style guide, revise up to twice on objection, put the question of consent to a person, and apply only upon assent. The following theorems concern its meaning. Each quantifies over worlds; none mentions syntax.

TheoremContent
consent_of_ackShould any acknowledgement appear in the transcript, in any world, the owner answered affirmatively concerning some patch.
ack_quotes_consented_patchThe patch acknowledged is the patch consented to, the two occurrences being the same patch.
guide_onceThe style guide is consulted exactly once in every world: sharing as a counted fact.
draft_count_le_threeAt most three drafts are requested, in every world.
level_hardenPatchThe workflow sits at branch, by reflexivity, so the finite-cost-tree results apply to it.
bill_hardenPatchThe cost tree has nine leaves with extremes 5 and 15; the reachable bills are exactly {6, 7, 10, 11, 13, 14, 15}, with attaining worlds exhibited, and the tree's minimum of 5 is proved unattained.

The last entry deserves emphasis. A bound that is sound and not attained is a weaker statement than a bound that is met, and the distinction is recorded in the library rather than elided: the tree over-approximates by one consultation, because approval at a given round makes one arm of the tail unreachable.

Execution against a live agent

The same plan executes against Claude Code through the Agent Client Protocol adapter (claude-agent-acp 0.64.0, August 2026), in a scratch directory, with the consent question routed to the keyboard. One run consumed seven consultations over roughly eighty-four seconds:

tool cat                 (text)     Write out the house style guide…   -> Lead with the outcome…
model author   model=deep (text)    Draft a patch satisfying…          -> a unified diff, bounds-checked
model reviewer-correct   (verdict)  …is this patch correct?            -> approve
model reviewer-secure    (verdict)  …is this patch secure?             -> approve
model reviewer-simple    (verdict)  Could this patch be simpler?       -> approve
person owner             (flag)     Apply this patch?                  -> yes
tool apply               (ack)      Apply: …                           -> done

bill: 7 consultations        ok  bill ∈ [6,7,10,11,13,14,15]
ok  the guide was read exactly once         ok  at most three drafts
ok  consent ⇔ the apply question was put    ok  the act wrote the consented patch
ok  the run certifies

The replies of a live model constitute one world among many, which is why the theorems transfer without weakening. Had the reviewers objected, the run would have taken a revision round and landed on a different member of the same proved set. The file left in the scratch directory was in fact hardened: the parsing routine was rewritten to accept buffer sizes and to bound every copy. A second run, differing only in the answer given to the consent question, consumed six consultations, produced no acknowledgement, and left the file untouched.

Part VII The boundary of proof

A proof is informative in proportion to the clarity of its boundary. Four matters are trusted, and each is stated in the source rather than concealed within a theorem.

  • The decoders. One total parser attends each code. How a particular English sentence tokenises is not a proposition the kernel can settle, so sixteen measured replies are pinned as tests. The parser fails closed: a word of refusal anywhere in a reply denies, whereas assent must constitute the whole reply, on the ground that no rule admitting Yes, apply it can exclude I cannot approve this patch.
  • Adapter fidelity. That the process at the far end of the pipe relays the model faithfully is an empirical assumption, and it is labelled as one.
  • The permission grant. The runtime authorises tool calls within the working directory of its own session. Declining them is not the conservative alternative it appears to be: a refused permission does not terminate the turn, and the turn completes normally with prose in place of an act, at considerable cost in tokens and with no protocol-level signal distinguishing it from an answer.
  • The log. The certificate warrants a claim about the table a run recorded, from which one discipline follows without exception: nothing may be written into the table that no party said. When decoding fails after its retries, the run is abandoned and the unreadable reply is quoted, because a defaulted answer in a table without provenance is indistinguishable from an answer given.

Coda

Three layers, one function between the first two, and one oracle between the second and the world:

A meaning, consisting of total answer sheets and the dialogues that consult them, chosen for comprehension and uncomputable by design.
A representation, first-order and with binders, each of whose operations is proved to commute with its meaning, and whose surplus structure funds analyses the meaning cannot support.
A runtime, the same fold supplied with an oracle in IO, each of whose runs carries a decidable certificate of agreement with the mathematics.

The property purchased by the arrangement is the one the discipline exists to secure: a workflow value may be treated as being its meaning. When a run reports that the guide was consulted once, the report is not an observation about that run. It is a theorem about every run, and the execution is evidence that the machinery beneath the theorem told the truth.
